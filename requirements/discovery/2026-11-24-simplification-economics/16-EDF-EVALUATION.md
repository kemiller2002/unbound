## EDF method as documented

*Source pass: Clarity, EDF and architecture.*

**What EDF is, in its own words.** "A systems understanding framework with a diagnostic grammar ... used to explain how a system produced an outcome and to identify the highest-leverage opportunities for influencing future outcomes"; "not primarily a decision framework" (echelon-diagnostic-framework@710d54c:docs/edf/specification.md:11-17). Specification v0.3, status *working draft* (echelon-diagnostic-framework@710d54c:docs/edf/specification.md:1-5).

**Diagnostic grammar (required sequence, echelon-diagnostic-framework@710d54c:docs/edf/specification.md:39-54):** 1 System Context (Primary System, Context, Focus) -> 2 Outcome (factual, not interpretive) -> 3 Manifestation(s) (observable signals) -> 4 Origin Network (technical, human, organizational, environmental, financial, regulatory; "rather than a single root cause") -> 5 Propagation (physical, informational, organizational, financial, human) -> 6 Evaluate Evidence ("Separate direct observation from inference") -> 7 Control Points ("may differ from origins") -> 8 Rank Control Points (influence, controllability, cost, confidence; "does not need false precision") -> 9 Diagnostic Sufficiency ("Do we understand enough to take the next responsible action?").

**Required output elements (echelon-diagnostic-framework@710d54c:docs/edf/specification.md:150-168):** System Context, Primary System, Context, Focus, Outcome, Manifestation(s), Origin Network, Propagation, Evidence, Control Points, Control Point Ranking, Confidence, Diagnostic Sufficiency, Unknowns, Next Responsible Action. Template: echelon-diagnostic-framework@710d54c:docs/edf/templates/edf-2-complex.md.

**Levels (echelon-diagnostic-framework@710d54c:docs/edf/complexity-levels.md:9-15, escalation triggers echelon-diagnostic-framework@710d54c:docs/edf/complexity-levels.md:101-115):** EDF-0 rapid, EDF-1 standard (several plausible origins), EDF-2 complex (multiple interacting systems, disputed origins, higher consequence). "Consequences are high or action is irreversible -> increase depth regardless of label." All eight recommendations here meet at least one EDF-2 trigger except R5 (EDF-1).

**Evidence boundary (respected throughout).**
- "Coherent enough to use as a working diagnostic grammar. Its performance claims are much less mature." Not established: cross-executor reproducibility, causal improvement from System Context, better control points than alternatives, evidence-sensitive updating, superiority to natural analysis or neutral structure, validated quantitative confidence (echelon-diagnostic-framework@710d54c:docs/edf/README.md:17-35).
- Registry state (2026-09-22): HY-EDF-004 (better control points) *suggestive*; HY-EDF-005 (independent executors agree) *unsupported*; HY-EDF-008 (value beyond neutral structure) *unsupported*; HY-EDF-007 (Origin Network vs Propagation distinct) *suggestive* (echelon-diagnostic-framework@710d54c:research/registries/hypothesis-registry.json).
- Confidence labels are qualitative, not probabilities: Low, Low-Medium, Medium, Medium-High, High (echelon-diagnostic-framework@710d54c:docs/framework-engineering/claim-and-confidence-policy.md:61-71).
- Control-point dimensions "are heuristics, not a validated scoring system ... no fixed weights" (echelon-diagnostic-framework@710d54c:docs/framework-engineering/claim-and-confidence-policy.md:123-127); "leverage" is a heuristic judgment (echelon-diagnostic-framework@710d54c:docs/edf/model.md:131-133).
- Diagnostic Sufficiency "is action-relative. It is not a certificate that the diagnosis is true or complete" (echelon-diagnostic-framework@710d54c:docs/edf/README.md:95); "Higher-consequence or irreversible actions require stronger evidence" (echelon-diagnostic-framework@710d54c:docs/framework-engineering/claim-and-confidence-policy.md:115-121).
- Independence: "Named analytical lenses produced by one model ... are not independent replications" (echelon-diagnostic-framework@710d54c:docs/framework-engineering/claim-and-confidence-policy.md:91-97); Diagnostic Calibration was **not** used because it requires materially independent analyses (echelon-diagnostic-framework@710d54c:docs/edf/diagnostic-calibration.md:15-21).

**Adaptation declared.** EDF diagnoses how an outcome was produced. The eight items are prospective recommendations. Each EDF record therefore diagnoses the **observed condition the recommendation responds to** (the Outcome field states only documented facts), and records the recommendation's own predicted outcome separately as `prospective_outcome_hypothesis`, which is outside EDF's diagnostic scope. Each record also carries a `claim_state` for the recommendation's core claim using the claim-policy vocabulary (echelon-diagnostic-framework@710d54c:docs/framework-engineering/claim-and-confidence-policy.md:47-59); that policy governs EDF research claims, so applying its states to Unbound claims is the evaluator's adaptation. Prior use: the landscape transaction-economics package used EDF fields informally ("These are **hypotheses**, not observed universal causes", daf-landscape:research/transaction-economics-evidence-package-001-2026-11-11.md:82-87); Echelon's `edf-diagnostic-packet` "does not perform an EDF diagnosis" (Echelon-AI-Native-Enterprise-Design-Framework@763ff8c:case-studies/daf/generated/analysis.md:309-311).
