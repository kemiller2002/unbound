## Next Best Action approach

*Source pass: Friction, configuration and dashboards.*

This section implements UNB-SMP-DSH-001.

**Meaningful interventions.** An NBA must be a registered Intervention type. Each type has a triggering rule or metric threshold, cited evidence, an expected outcome, and the domain command it opens. Examples:
- aged provider Unknown → "Query provider status", never "Reissue" (RR-REQ-X-004-r1);
- charity evidence nearing expiry → deterministic refresh (UNB-RCN-GRT-014);
- unexplained cash break → open exception and hold affected statements (RCD-020);
- donor: held grant needing a response → respond to the information request;
- donor: fund approaching dormancy → keep active;
- advisor: co-advisor approval pending;
- sponsor: pack version superseded → review diff and attest.

**Ranking.** A published deterministic rule combines:
- harm avoided or value protected (amount at risk, a legal exposure class);
- legal or contractual deadline proximity;
- customer impact (an external party waiting);
- SLA risk;
- effort.

Weights are an operations-owner decision. Ties break by earliest legal deadline. A rank explanation is always available in text. If an input is missing, the list falls back to SLA-risk sort (UNB-UI-S-008) and flags the fallback.

**Evidence.** Each NBA shows its evidence fields with source and freshness (UNB-UI-G-003). AI may summarise the evidence, labelled as machine-generated, but cannot add evidence or change rank.

**Authority boundaries:**
- Authority is evaluated server-side against the authority matrix (UNB-RCN-PLT-005) at render and again at command time.
- An action outside the viewer's authority shows as unavailable, with the reason and the role that can act (FORMA-GAP-11).
- Selecting an NBA opens the authoritative command with state re-checked.
- An NBA never executes A3 or higher actions, never bypasses holds, and never exercises discretion reserved to the sponsor (IRC §4966(d)(2)).
- Outcomes (accepted, dismissed, result) are tracked to validate the ranking.

## Drill-down, evidence, accessibility, exception queues, widgets, embedding

*Source pass: Friction, configuration and dashboards.*

**Drill-down.**
- Every tile drills to the population that produced it. For example, outcomes at risk → the exception inbox filtered by reason and age → the case workspace (UNB-UI-S-014) → the evidence and the source event.
- Drill-down never broadens scope. Filters are typed and permission-aware (shared dashboard framework).
- Cost figures drill to AttributedCost rows and then to the source events (UNB-XIN-ECO-022 AC-1).

**Evidence and provenance.**
- Every figure shows its as-of time and freshness (UNB-UI-G-003/F-006), its metric version, and either a snapshot id (official) or a watermark (live estimate).
- Official and estimated figures are labelled distinctly.
- No total is shown as reconciled while any component is stale (UNB-UI-S-011).
- Bitemporal "as reported" vs "as corrected" views are kept, and restated history is visibly marked.

**Accessibility.**
- WCAG 2.2 AA (UNB-UI-G-008/A-001).
- Every chart has a title, labelled axes, value labels, a text summary and a keyboard-reachable data table (UNB-UI-DS-018).
- Status is never shown by colour alone.
- Counter-metrics cannot be hidden on mobile (report 11).
- Mobile: donor, advisor and approval views are phone-complete; finance and close are desktop-first (RCD-026; UNB-UI-G-009).

**Exception queues.** The single exception inbox holds rule-created WorkItems only (RR-REQ-X-048-r2; UNB-UI-S-008). Dashboards link to it and never duplicate it as another queue. Routine items never appear (UNB-RCN-PLT-006).

**Widgets.** Widget definitions are versioned. Each declares a data contract, loading, empty, error, Unknown and stale states, and a safe drill-down (REQ-X-050). Widget assistance contracts follow RR-REQ-X-051-r2.

**Embedding.**
- Release 1 offers only a read-only grant-status card (UNB-UI-W-001), served from the sponsor's Unbound origin with a short-lived, sponsor-scoped token.
- Action embeds are excluded until the widget host exists (DG-03).
- Partner and sponsor embedding of dashboards is deferred.
- No third-party tracking.

## Single source of definitions for dashboards, exports and print

*Source pass: Friction, configuration and dashboards.*

This section implements RR-REQ-X-043-r1. It supersedes having three registries:
- the REQ-X-043 semantic layer;
- the UNB-XIN-ECO-007 economics registry;
- the REQ-X-049 work-queue metric contracts.

It also operationalises the parity requirements MON-023 and INT-016.

1. **One Metric Registry.** Economics and work-queue metrics are entries in it, not separate registries. Each entry carries the RR-REQ-X-043-r1 fields, plus decision, owner, expected action, counter-metric and suppression rule.
2. **Decision gate.** A metric without a decision supported cannot be registered. The 14 removed metrics are the precedent.
3. **Snapshot binding.** A figure is computed from one of:
   - a sealed FinancialSnapshot (UNB-XIN-EVA-003), for official and print figures;
   - a read model with a declared watermark, for live estimates.

   Every rendering, whether Forma tile, CSV, JSON or API export, or Folio print, carries metric id@version, snapshot id or watermark, scope and as-of time.
4. **Parity test.** For a given scope and snapshot, the dashboard, export and printed values must be identical. Statement publication is blocked on mismatch (SPS-DSH-001).
5. **Definitions travel with the figure.** Exports and prints embed the definition version and, for estimates, the label "Management estimate, not a financial statement" (report 11).
6. **No ad hoc computation in presentation layers.** Forma and Folio receive computed values and definitions. They never compute metrics, as the 19-questions architectural split requires.
7. **Change control.** A material definition change creates a new version, keeps the old one for comparison, and visibly marks restated history.
